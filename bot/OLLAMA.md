# Подключение Ollama: локально и в продакшене (Tailscale)

Бот обращается к Ollama по HTTP. **Код менять не нужно** — адрес задаётся
переменной `OLLAMA_URL`. Так что одна и та же сборка работает и с локальной
моделью, и с удалённой (например, у ребят дома через Tailscale).

## Два сценария

### 1. Разработка — модель на этой же машине

```env
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3.5:4b
```

> `127.0.0.1`, а не `localhost`: Ollama слушает только IPv4, и Node иногда
> пытается достучаться до `::1` и падает с `fetch failed`.

### 2. Продакшен — бот на VPS, Ollama дома у ребят

Бот (VPS) и хост с Ollama объединены в приватную сеть Tailscale. У домашнего
хоста в Tailscale стабильный адрес вида `100.x.y.z` (или MagicDNS-имя):

```env
# на VPS
OLLAMA_URL=http://100.101.102.103:11434
OLLAMA_MODEL=<vision-модель>
```

Ничего в интернет не выставляем — доступ закрыт на уровне сети Tailscale.

## Failover: несколько адресов

`OLLAMA_URL` принимает **список через запятую**. Бот пробует адреса по порядку
и переходит к следующему, если текущий не ответил:

```env
OLLAMA_URL=http://127.0.0.1:11434,http://100.101.102.103:11434
```

Полезно, когда есть локальная копия модели и удалённая. По умолчанию адрес один
— поведение не меняется.

> Важно: failover помогает только между **разными** хостами. Два адреса на одну
> и ту же машину не дают отказоустойчивости.

## Ретраи и общий бюджет времени

- `LLM_RETRIES` — число повторов на каждый адрес (пауза растёт: `LLM_RETRY_DELAY_MS`, 2×, 3×…).
- `LLM_TOTAL_BUDGET_MS` — общий лимит на все попытки и адреса. Повторы делаются
  только пока не истёк бюджет, поэтому пользователь не ждёт бесконечно.

Повторяются только сетевые сбои, таймауты и ошибки 5xx. Ошибки 4xx (например,
неверная модель) не повторяются — сразу идём дальше / падаем.

## Фолбэк на OpenAI

Если все адреса Ollama недоступны, можно уйти на внешний OpenAI-совместимый API:

```env
LLM_FALLBACK_TO_OPENAI=true
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

По умолчанию `false`: фото шильдика **не покидает приватный контур**. Включайте
осознанно — при фолбэке фото уходит во внешний сервис.

## Диагностика при старте

При запуске бот проверяет каждый адрес из `OLLAMA_URL` (`GET /api/tags`) и пишет
в лог, доступен ли хост и есть ли нужная модель. Проверка **не роняет** бота —
если Ollama недоступна, будет `warn`, а бот продолжит работать.

Отключить: `LLM_HEALTHCHECK=false`.

## Всё, что нужно на стороне хоста с Ollama

1. **Слушать не только localhost** (иначе Tailscale-адрес недоступен):

   ```ini
   # /etc/systemd/system/ollama.service.d/override.conf
   [Service]
   Environment="OLLAMA_HOST=0.0.0.0:11434"
   ```

   ```bash
   sudo systemctl daemon-reload && sudo systemctl restart ollama
   ```

2. **Vision-модель.** `qwen3.5:4b` — текстовая, для шильдиков нужна VL-модель
   (например `qwen2.5vl`, `llava`, `minicpm-v`). Укажите её в `OLLAMA_MODEL`.
3. **Tailscale** на обеих машинах, в одной сети/ACL.
4. `OLLAMA_KEEP_ALIVE` (по умолчанию `30m`) держит модель в памяти — первое фото
   не ждёт холодной загрузки. Бот дополнительно «прогревает» модель при старте.

## Безопасность

У Ollama **нет** авторизации. Не выставляйте порт в интернет. Единственный
приватный канал — Tailscale (или аналогичный туннель). В коде аутентификация
намеренно не добавлена: доступ закрывается на уровне сети.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Адрес(а) Ollama, можно список через запятую |
| `OLLAMA_MODEL` | `qwen3.5:4b` | Имя модели (нужна vision-модель) |
| `OLLAMA_KEEP_ALIVE` | `30m` | Сколько держать модель в памяти |
| `LLM_TIMEOUT_MS` | `180000` | Таймаут одной попытки, мс |
| `LLM_TOTAL_BUDGET_MS` | `180000` | Общий лимит на все попытки/адреса, мс |
| `LLM_RETRIES` | `3` | Повторов на каждый адрес (0 — без повторов) |
| `LLM_RETRY_DELAY_MS` | `1000` | Базовая пауза перед повтором, мс |
| `LLM_FALLBACK_TO_OPENAI` | `false` | Уходить на OpenAI, если Ollama недоступна |
| `LLM_HEALTHCHECK` | `true` | Проверять Ollama при старте |
| `LLM_HEALTHCHECK_TIMEOUT_MS` | `5000` | Таймаут проверки, мс |
